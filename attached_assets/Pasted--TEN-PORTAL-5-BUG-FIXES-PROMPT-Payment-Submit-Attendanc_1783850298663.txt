## CONFIRMED ROOT CAUSES (read before coding)

- **Submit button double-request**: After first successful UTR submit, `submitTenureUtr()` calls `checkTenurePayment(false)`. The status API returns `requiresPayment: true` (because `shortCoursePaid` is still false — admin hasn't approved yet). This re-shows the QR overlay with the form. Student can enter UTR again and click submit a second time. The server blocks the second submission, but the UI never told the student the first one already worked.

- **Attendance ring/cards show %**: `updateAttRing(pct)` at line 5058 sets `label.textContent = pct + '%'`. Element id `attRingPct` (line 1898) shows `0%`. Cards `selfAttPct`, `classAttPct`, `combinedAttPct` (lines 2278, 2283, 2288) all show `0%`. These are set in the JS block around line 3584–3598.

- **WhatsApp joiner wizard result shows %**: `wizardStep3ResultPct` (line 5320) shows `0%`. Set at line 5511: `document.getElementById('wizardStep3ResultPct').textContent = data.student.calculatedAttendance + '%'`. The API already returns `presentCount` and `daysNeededToAttendMore`.

- **Email to change**: `public/registration-success.html` line 96: `support@tenecosystem.com` → must be `hr@entrepreneurshipnetwork.net`.

- **Post-approval redirect**: `routes/adminPortal.js` route `POST /payments/verify/:paymentId` (line 162). When admin approves from the **Payments tab**, this route handles it. It does NOT set `student.shortCoursePaid = true` for tenure payments — only cert/fine purposes are handled. The `tenure-payment/approve` route (line ~286) DOES set it, but that's only for the Tenure Payments tab. Admin sees tenure payments in BOTH tabs and often uses the Payments tab.

## FIX 2 — Post-Admin-Approval Redirect Fix

**File to change:** `routes/adminPortal.js`

### Problem:
Route `POST /payments/verify/:paymentId` (line 162) handles payment approval from the Payments tab. For tenure payments (purpose starts with `tenure_`), it does NOT set `student.shortCoursePaid = true`. So after admin approves from the Payments tab, the student's `shortCoursePaid` field stays `false`, and on next login the payment wall re-appears.

### Fix:

Inside the `if (action === 'approve')` block of `POST /payments/verify/:paymentId`, find the block that handles `cert_expert`, `cert_nano_degree`, `cert_fellowship`, `fine_low_attendance`. AFTER all those existing `if` checks (but still inside the `try` block and still inside `if (action === 'approve')`), add:

```js
// If this is a tenure payment, unlock student access
if (payment.purpose && payment.purpose.startsWith('tenure_')) {
  try {
    const tenureStudent = await Student.findById(payment.studentId);
    if (tenureStudent) {
      tenureStudent.shortCoursePaid = true;
      tenureStudent.shortCoursePaymentVerified = true;
      tenureStudent.shortCoursePaymentId = payment.orderId || payment._id.toString();
      await tenureStudent.save();
      console.log('[Admin] Tenure payment approved — student access unlocked:', tenureStudent.employeeId);
    }
  } catch (tenureErr) {
    console.error('[Admin] Error unlocking tenure student:', tenureErr.message);
    // Do not fail the whole approval — log and continue
  }
}
```

Place this block AFTER the existing `fine_low_attendance` if-block and BEFORE the `Notification.notifyStudent(...)` call.

Also, in the `if (action === 'reject')` block of the SAME route, after `payment.save()`, add:

```js
// If tenure payment rejected, reset shortCoursePaymentId so student can resubmit
if (payment.purpose && payment.purpose.startsWith('tenure_')) {
  try {
    const tenureStudent = await Student.findById(payment.studentId);
    if (tenureStudent) {
      tenureStudent.shortCoursePaymentId = null;
      await tenureStudent.save();
    }
  } catch (e) {
    console.error('[Admin] Error resetting tenure student on reject:', e.message);
  }
}
```

Place this BEFORE the `Notification.notifyStudent(...)` call in the reject block.

## FIX 4 — Attendance Ring and Cards: Show Days Not Percentage

### Fix 4A — Change the ring label from % to days:

Find the `updateAttRing` function (line 5058):

```js
function updateAttRing(pct) {
  var circle = document.getElementById('attRingCircle');
  var label = document.getElementById('attRingPct');
  if (!circle || !label) return;
  var circumference = 150.8;
  var offset = circumference - (Math.min(pct, 100) / 100) * circumference;
  circle.style.strokeDashoffset = offset;
  circle.style.stroke = pct >= 75 ? '#10b981' : pct >= 50 ? '#f59e0b' : '#f43f5e';
  label.textContent = pct + '%';
}
```

```js
function updateAttRing(pct, presentDays) {
  var circle = document.getElementById('attRingCircle');
  var label = document.getElementById('attRingPct');
  if (!circle || !label) return;
  var circumference = 150.8;
  var offset = circumference - (Math.min(pct, 100) / 100) * circumference;
  circle.style.strokeDashoffset = offset;
  circle.style.stroke = pct >= 75 ? '#10b981' : pct >= 50 ? '#f59e0b' : '#f43f5e';
  // Show days present instead of percentage
  var days = (presentDays !== undefined && presentDays !== null) ? presentDays : Math.round(pct);
  label.textContent = days + (days === 1 ? ' day' : ' days');
}
```

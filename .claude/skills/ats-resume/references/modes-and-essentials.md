# Modes and essential signals

## BUILD

User has no usable resume. They have some mix of skills, projects, jobs, education.

1. Inventory everything
2. Pick target role / playbook
3. Rank essentials (below)
4. Write on the skeleton as if RECREATE produced a blank page
5. If jobs are thin, lead with Projects
6. Ask at most one metrics question after the first draft if bullets lack scope

Do not refuse to build because the profile is junior. Build the strongest truthful page, then list fact gaps.

## RECREATE

User has a file that is designed, scanned, two-column, icon-heavy, or poorly parsed.

1. Recover reading order (top-to-bottom, left column then right only if you must)
2. Rebuild every true field onto the single-column skeleton
3. Do not drop a job, degree, or project unless the user agrees or it is older than the 10–15 year window and off-target
4. Then run CONVERT-quality rewrites so recreation is not a clone of a bad structure

Recreation means new document, same facts.

## CONVERT

User has content that would be rejected.

1. Diagnose ATS-reject and HR-reject
2. Keep essentials, drop noise
3. Rewrite duties to impact
4. Align keywords only where evidenced
5. Stop at the ship gate

CONVERT may change wording and order. It may not change biography.

## What “essential” means

Essential = a recruiter or ATS would search or skim for this, and the ledger proves it.

Not essential = nice, old, off-target, or unevidenced.

### Essential skills

Keep a skill if **both** are true:

- The JD or role playbook cares about it
- Experience or a project shows it

Order: JD required → JD preferred → other evidenced tools that define the stack.

Cap the primary skills line at about 12–16 terms. Extra evidenced tools can sit in bullets only.

Drop:

- Soft skills as a list
- Tools not used
- Beginner noise that hides the real stack (Microsoft Word on a backend resume)

### Essential experience

Keep a role if it is:

- Recent (last 10–15 years), or
- The clearest proof of the target function, or
- The only evidence for an essential skill

Compress or drop:

- Unrelated student jobs when stronger projects exist
- Duplicate duties across two similar roles (keep the stronger)
- Pre-history that fights the target title

Each kept role needs a correct header and bullets that prove function, not tasks.

### Essential projects

Keep a project if it:

- Proves a JD skill that jobs do not show, or
- Is the main hire signal (new grad, switch, freelance), or
- Has a real stack and an outcome

Rewrite every kept project as problem → stack/role → outcome.

Drop name-only repos, course clones with no extra work, and five tiny weekend demos (merge or pick the best two).

## Ranking (use this order)

1. Matches the target role and is evidenced
2. Recent
3. Has scale or outcome
4. Unique (only place that skill appears)

If two items compete for space, keep the higher rank.

## Page budget

1 page: 1 summary, 1 skills block, 2–3 roles or 1 role + 2–3 projects, education.

2 pages: add older essential roles and one more project. Nothing else.

## Mapping table (required in the working notes)

| Essential item | Type | Evidence | Where it goes |
|---|---|---|---|
| React.js | skill | Shop cart project | Skills + project bullet |
| SDE intern | experience | Summer 2025 | Experience, 3 bullets |
| Fraud dashboard | project | SQL + Tableau | Projects, above internships if that is the signal |

If a JD term has no row, it is Not claimed.
